# Remote Channel 正文处理审计

第 285 阶段第四片在现有加密待确认箱中保存打开、忽略和正文过期的最终处理记录。正式 Release 保持 `v0.1.22`，Room 保持 v40；本次只把收件箱明文 schema 升至 v3，AES-GCM 外层版本、偏好文件与 Keystore 密钥不变。

## 处理语义

| 结果 | 记录时机 | 正文与用户行为 |
| --- | --- | --- |
| `OPENED` | 确认卡“打开远程草稿”的决定持久提交 | 删除待确认正文，随后允许导入可编辑草稿；不发送、不创建 Agent Run |
| `IGNORED` | 列表或确认卡的忽略决定持久提交 | 删除待确认正文，不导入草稿 |
| `EXPIRED` | 本机检测到入箱满 24 小时并持久提交清理 | 删除待确认正文，拒绝旧确认卡继续打开 |

列表里的“打开”只展示确认卡，不删除正文或写 `OPENED`；确认前中断仍可从列表恢复。`OPENED` 只表示用户决定已保存，不证明编辑器已显示、消息已发送或任务已执行。决定先提交，编辑器导入不与快照写盘构成跨组件事务。

过期依据本机 `acceptedAtMillis`，恰好 24 小时即过期，不能用发送方时间延长保留期。检测触发于收件箱重建、待确认列表读取、单条接收或最终决定；仍是惰性清理，不增加精确计时器，也不保证到点自动执行。记录时间是实际检测并保存的本机时间。时钟回拨不提前过期，审计保留实际墙钟值，不伪造单调顺序。

## 记录与容量

每条记录恰好包含：

| 字段 | 含义与约束 |
| --- | --- |
| `recordId` | 独立随机 UUID，不参与消息授权或重放判断 |
| `messageIdentitySha256` | `channelId + NUL + senderId + NUL + messageId` 的 UTF-8 SHA-256，小写 64 位十六进制 |
| `acceptedAtMillis` | 本机入箱时间，正整数 Unix 毫秒 |
| `recordedAtMillis` | 本机保存处理结果的时间，正整数 Unix 毫秒 |
| `disposition` | 严格为 `OPENED / IGNORED / EXPIRED` |

记录不含正文、原始消息/发送方 ID、nonce、远端会话标签、URL、receipt、工具参数或凭据。UUID 避免去重窗口滚动或墙钟回拨后把不同次处理混为一条。最近 128 条按提交顺序保留，超限只滚动旧审计，不淘汰正文、去重或 outbox。它不是永久历史，也不替代已有有界重放窗口。

设置 → 远端身份配对的“处理记录”只读，默认收起，显示最近 10 条结果、摘要和本机时间；不提供重新打开正文、执行、导出或网络操作。通知仍只进入待确认列表。

## 原子性与恢复

`InMemoryRemoteChannelInbox` 同次提交正文删除和审计追加，保留消息/nonce 去重及 batchStates 的 cursor/receipt。Gateway 共享锁协调接收、读取与最终决定，不同 Gateway 对同一正文只能成功处理一次；旧内存正文与当前正文不一致时拒绝决定。

决定写失败不交付草稿、不追加成功审计，原卡片保留供重试。过期清理写失败冻结当前视图并返回不可用，不展示未提交的过期记录。正文已过期或被其他入口处理时，确认卡撤销缓存，不导入旧正文。密文或审计字段损坏不清空状态、重放账本或静默退回空审计。

codec 严格核对 v3 根字段、记录字段、整数/UUID/SHA-256/枚举、容量和重复 recordId。旧 v1/v2 读取补空审计，保留原正文、去重和批次状态；不追造升级前历史，下次成功提交写 v3。

## 验证边界

JVM 覆盖原子决定、并发/重复、旧正文拒绝、24 小时边界、回拨、失败、容量、codec 和兼容。Redmi 用 UUID 偏好与专属 Keystore 验证密文重建/升级/损坏；确认 UI 注入隔离 inbox，并显式设为前台就绪 ViewModel，执行生产处理器，不运行用户 Room/Agent 恢复或调用模型。完整 MainActivity 的默认 ViewModel 构造和分享行为由既有回归另验。

本片不新增公网 transport 证据，不把本地构造 cursor/outbox 计作服务端 ACK。自然系统周期、Doze、LMK、系统重启及生产发送方仍待后续。实际命令、失败与结果见[验证报告](verification-report.md)。
