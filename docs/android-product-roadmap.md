## 1. 当前基线：原七点已完成实现，验收范围有边界

基线为 `v0.1.24 / versionCode 25`，发布前主仓基线为 `44f3961`。模块为 `app / baselineprofile / shared`，Room v44。正式包升级、启动及本轮 POCO 真机 M1 回验已通过；详细证据以[发布记录](android-v0.1.24-release.md)及各专项报告为准。

| 原顺序 | 已具备的实现 | 独立缺口，不重新列为从零开发 |
| --- | --- | --- |
| 1. Remote Channel | cursor、批次、ACK、持久重试/发送队列、后台收件与通知独立开关 | 稳定部署、容量回收、真实通知和长期运行 |
| 2. MCP | `McpSessionRegistry`、Streamable HTTP、legacy SSE、会话撤销和取消 | Context7 `query-docs`、真实外部 SSE、OAuth、stdio、后台 MCP |
| 3. Context / Memory | Memory CAS、实际输入 snapshot、有界提取压缩、恢复核验、显式整理建议 | 长会话效果、用户可见上下文占用/消耗、自然系统恢复；整理仍不自动写记忆 |
| 4. Skill / 插件 | GitHub Skill、签名 manifest、公钥确认、回滚、SAFE 前台宿主调用 | 完整正式包入口联合；任意插件代码执行尚未开放 |
| 5. 多 Agent | 1–2 个只读 child、持久 checkpoint、取消/失败聚合、结果单次消费 | 精确共享扣账、token/费用预算、完整产品联合；旧批次不能自动恢复执行 |
| 6. Workspace / Browser / GenUI | transcript、有界命令会话、静态 HTML 语义 DOM、审批导航、本机输入草稿、版本化显式 action | 文件产物交付入口、真实渲染 DOM/网页输入、复杂文件与浏览器任务 |
| 7. KMP / iOS | 共享协议/codec、若干 iOS actual 和只读宿主技术验收 | iOS 产品暂停；不追求平台能力强行对齐 |

此前 Debug、隔离 Room 或生产 UseCase 的成功，不能替代正式签名包完整功能验收。报告中的未通过 Run、`PARTIAL`、`COMMIT_UNKNOWN` 等事实继续保留。以上是实现基线与验收边界，不表示七个方向的长期产品工作全部结束。

## 3. 主线顺序与退出标准

| 顺序 | 阶段 | 用户获得什么 | 完成标准 |
| --- | --- | --- | --- |
| M1，已交付本轮增量 | 常用任务可用性、前置诊断与正式包闭环 | 发起前知道能做什么、缺什么；执行时知道停在哪里 | 本轮实现及发布范围见 v0.1.24 记录；八类联合验收未全部重跑 |
| M2 | 高频个人任务组合 | 从现有信息形成可确认的笔记、提醒和安排 | 三条任务从普通入口完成、可回读结果；拒绝和部分失败正确保留 |
| M3 | 文件任务与产物交付 | 选择文件、查看修改、保存并带走产物 | 一个真实文件任务走完导入、确认、写入、回读、导出，覆盖冲突/取消 |
| M4 | 长会话、上下文与消耗可控 | 看见上下文占用和调用消耗，长任务延续目标与约束 | 固定长会话语料达到保真门禁；统计有来源，未知项明确显示 |
| M5，满足前置后选一条 | 动态浏览器、stdio/代码运行、扩展多 Agent | 增加现有工具无法完成的明确任务 | 先验收隔离、生命周期、预算和取消，再验收该任务；不同时铺开三条 |

先按 M1 → M2 → M3 → M4 推进。M5 是条件阶段；没有明确任务和前置证据时不启动。这里按交付结果排顺序，不预定完成日期或提前修改版本号。

### M1：常用任务可用性与前置诊断

**第一片确定为常用任务可用性。** 复用 `AgentLaunchPreflightCoordinator`、已发现且已登记的应用目录、`DeviceObservationController.health()`；把实际条件投影到“常用任务”和任务发起入口。当前四个模板是静态目标，规划层才执行应用交集校验，用户可能选择当前设备无法执行的天气任务。

任务显示“可运行 / 需要配置 / 当前不支持”及具体原因。检查当前 Provider、模型、Profile 的工具交集、目标应用和设备能力状态；权限由用户从系统页面授权。天气包不存在时直接解释原因，不静默改用别的应用。读取期间换模型、撤权或切换目标后重新核对；准备阶段不调用模型、不创建 Workflow/Run、不执行设备动作。最终执行继续走原 Gate，界面判断不代替授权。

第二片收敛现有任务中心和审批反馈：区分规划、执行、等待审批、验证和已停止，展示阻塞原因与当前步骤。用户在目标应用停留时也应能知道任务还在运行、等待还是已失败；先复用现有页面/审批浮层，是否增加持续进度入口由实际使用证据决定。保留已经存在的停止、重试和目标级完成判定，不另建一套 Run 状态机。

M1 的正式包清单固定为以下八类，使用指定 POCO F2 Pro（`31936bb6`）和用户配置的真实模型，记录该次 APK/版本/Run：

1. 普通设置入口完成 Provider、模型及 Agent Profile 配置，并发起普通对话。
2. 无模型、缺 Profile 工具、目标包缺失、服务未授权/未连接：提示能定位到缺口，未创建任务或产生动作。
3. 普通个人任务入口完成一个现有计算器任务，独立回读结果。
4. 普通编辑器完成设置搜索任务，确认限定应用和完成标准，输入隐私保持。
5. 一条 SAFE 本地查询无需申请设备权限，能查看当前事实。
6. 拒绝一次动作审批：没有动作结果，任务保持真实失败/拒绝状态。
7. 停止模型等待或待审批任务：迟到回调不能继续写入或执行。
8. Activity 重建后从任务中心查看同一 Run 和结果，原会话、配置与旧审计保持一致。

新问题只修复与这份清单有关的缺口。自然 LMK/Doze/重启、长期 Remote 和复杂设备任务不加入 M1 退出条件；已有专项通过项只在正式包联合链需要时复验，不逐阶段重跑全部矩阵。

### M2：把现有工具组合成高频任务

复用现有笔记、提醒、日历、知识、分享和通知草稿能力，新增重点是可复用入口、跨步骤稳定 ID/版本、部分结果和失败去向。单工具已验收能力无需重新实现。先交付以下三条组合，设备动作只用于必要且已登记的前台步骤：

| 任务 | 组合增量 | 验收事实 |
| --- | --- | --- |
| 分享/当前通知 → 笔记 → 一次性提醒 | 由用户选择来源、编辑草稿和时间；下一步绑定已提交笔记 ID | 旧通知移除拒绝；笔记和提醒可回读；第二步失败不抹掉第一步成功 |
| 当前日历 + 本地任务 → 今日安排草稿 | 经授权查询两类当前事实，生成有来源的安排，用户选择是否保存 | 时间/时区和记录身份一致；不直接改日历、不制造精确定时承诺 |
| 知识库问答 → 来源 → 保存笔记 | 结果保持文档身份/版本，保存前检查来源仍有效 | 删除或替换来源后不能沿旧结果写入；保存后可进入当前笔记 |

每条组合先对照已有入口确认实际缺口，再补最小实现；需要多源写入时承认分步提交，不宣称已有跨日历/Room/系统事务回滚。每条均包含成功、拒绝/取消和一处来源失效或部分失败；三条收口后进入 M3。

### M3：受控文件任务和可交付产物

先做文本/Markdown 文件任务，例如“选一份资料，生成摘要并导出 Markdown”。通过系统选择器把用户选定的有界文件导入私有工作区，展示目标路径、当前版本和修改预览，确认后写入；产物绑定 Run、文件身份、版本/摘要，点击时回读当前文件，再由用户选择导出位置。

`WorkspaceSandbox` 已有目录边界和 transcript，但普通文本写入仍是直接 `writeBytes`。引入覆盖/编辑前先补版本冲突检查与原子提交，不能把命令 transcript 当作文件版本或成功写入证明。冲突、路径逃逸、超限、取消及导出失败都要保留真实结果。第一片只开放实际需要的文件类型，不引入整机存储扫描、完整 shell 或开发环境安装。

退出时普通用户能导入资料、检查修改、回读产物并通过系统文件入口打开导出文件；一个新进程还能查到原 Run 与产物归属。原始文件、既有工作区文件和凭据不能被隐式打包到导出结果。

### M4：上下文效果与资源消耗

普通聊天已有增量模型摘要，Agent 历史已有确定性提取压缩，Run 已按请求累加 usage 和模型延迟；这些基础继续使用。新增先做三件事：

- 区分末次请求的上下文占用、整个 Run 的累计 token、模型请求耗时和审批/工具等待。服务未返回 usage 时显示未知/覆盖范围；字节与估算 token 分开，未知 context window 不显示伪精确百分比。
- 给摘要/压缩固定保真语料：用户目标、约束、已确认决定、失败和未完成项、来源身份/版本。压缩后的继续请求仍不能从省略正文推断成功，也不能把模型摘要写成正式记忆或执行事实。
- 在已有加载代次、删除代次和串行持久化上核验生成、切换、删除、停止的组合。只有具体竞争或多入口生命周期问题被复现，才做会话状态归属重构。

结构化摘要、尾部压缩指令和缓存统计先做可测量试验，再决定接入；不直接用参考项目的新类替换本项目架构。使用同一固定语料对照输入体积、usage 覆盖、延迟和关键事实保留，收益不足则保留当前策略。精确价格核算依赖真实 Provider 计费与模型元数据，缺失时不能宣称已实现。

### M5：满足前置再增加能力

| 方向 | 启动条件 | 第一片边界 |
| --- | --- | --- |
| 真实渲染浏览器 | 一个静态 HTML 无法完成的明确任务；M3 产物归属可用 | 可见宿主、当前页面 DOM/ref、导航撤销与逐动作审批；先只读，不先做登录/提交 |
| stdio / 代码沙箱 | 一个需要本地 MCP 或运行代码的任务；进程、网络/文件权限及取消机制验证通过 | 固定来源和最小能力面；超时/撤销清理子进程、失败不回退宿主 shell；不把 proot 自动当作安全隔离 |
| 多 Agent 扩展 | 单 Agent 的实际任务确有并行价值；先在当前边界补预算门禁 | 在现有两个只读 child 上完成原子预算预留/结算、父 deadline 和取消；通过后再扩能力，不先增加数量、写权限或递归 |

签名插件可继续承接 SAFE 宿主能力；执行插件代码必须另过沙箱门禁。ACP、大范围模型路由、开放插件市场、本地模型和云同步没有近期里程碑。

## 4. 独立待办与暂停项

| 待办 | 完成证据 / 启动条件 | 对主线的影响 |
| --- | --- | --- |
| Remote 稳定部署与容量回收 | 有明确部署目标；真实认证、cursor/ACK、断网重试、积压/过期/容量回收和服务运维记录 | 不阻塞 M1–M4；后台仍只收件，不自动运行 Agent |
| 真实通知 | 用户显式授权后，指定真机可见通知、点击导航和去重/撤权证据 | 不拿开关或 Worker 测试替代通知送达 |
| 自然系统恢复 | 自然 Doze/进程退出/重启的同 Run 前后事实、停止原因和新进程回读 | 无事件时记录待观察；不以循环强杀或模拟恢复无限延长主线 |
| 外部 MCP | Context7 `query-docs` 和一个明确的外部 legacy SSE 目标；用户前台确认与当前响应 | 端点 `/mcp` 不因响应包含 SSE 就算 legacy SSE 互通；鉴权失败单列 |
| 复杂设备任务与跨 Run 输入隐私 | 指定任务、指定应用和可独立回读的目标；输入回显/缓存跨 Run 的边界先定义 | 不扩大成任意 App，不沿用旧观察/授权 |
| OAuth、后台 MCP | 独立账户/令牌生命周期与授权设计，有实际需求 | 不并入现有 registry/SSE 的已完成结论 |
| iOS 产品 | 用户重新决定启动产品，并确定任务范围 | 当前暂停；共享契约维护只随 Android 实际变化进行 |

## 5. 推进规则

- 主线同时只有一个当前阶段。每轮记录该阶段的交付、实际缺口、有限退出标准和剩余项；临时可靠性修复必须挂回它服务的用户任务。
- 参考仓库按远端默认分支同步，并保存 commit 与来源；采用实现前重新点验相关代码、依赖和许可证。源码存在、自动化通过、真实模型、正式包产品联合分别记录。
- 局部改动做受影响验证；完整矩阵放在里程碑/发版门禁。长期待办有新事实才更新，已通过项只因相关代码变化或联合链需要才复验。
- M1 本轮实现与验证已纳入 v0.1.24，剩余项按发布记录区分；后续功能开发等待用户指定，不自动启动 M2–M4。本文后续阶段为计划，本轮未将其标记完成。
